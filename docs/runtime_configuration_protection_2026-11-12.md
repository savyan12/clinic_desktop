# إصلاح حماية ملفات تشغيل المنظومة

تاريخ التحقق: 12 نوفمبر 2026.

العمل هنا يخص إصلاح المصدر واختباره فقط. لم تُعد استعادة بيانات العميل، ولم تُعدّل قاعدة البيانات المستعادة أو إعدادات النسخة المثبتة، ولم يُغلق التطبيق الذي يعمل حاليًا.

كانت بعض تعديلات الحماية موجودة في ملفات المشروع عند بدء هذه الجلسة. تمت مراجعتها، وإكمال الحالات الناقصة، واختبار السلوك الفعلي على ملفات وقاعدة بيانات مؤقتة.

## الحماية الموجودة الآن

| الحالة | السلوك |
| --- | --- |
| حفظ إعدادات التشغيل | ملف مؤقت فريد في المجلد نفسه، كتابة كاملة وتثبيت بواسطة `sync_all`، ثم استبدال باستخدام `MoveFileExW` مع `MOVEFILE_WRITE_THROUGH` على Windows. لا يُختصر الملف الأصلي أثناء الكتابة. |
| إعدادات سليمة لم تتغير | لا تُعاد كتابة المحتويات؛ يُثبت الملف الموجود. |
| `install.json` مفقود أو مصفّر أو مبتور | تُقرأ `install.json.backup` وتُفحص حقولها وبصمتها، ثم يُصلح الملف الأساسي بنفس بيانات الاتصال وحالة التفعيل. |
| نسخة قديمة بإعدادات سليمة ودون نسخة إعدادات احتياطية | ينشئ أول تشغيل للبناء الجديد نسخة الإعدادات المحمية قبل الاعتماد عليها. |
| `mysql-root.cnf` تالف أو مفقود | يُعاد توليده من الإعدادات السليمة بنفس كلمة مرور MySQL، وبطريقة الحفظ الآمنة نفسها. |
| الإعدادات ونسختها الاحتياطية غير قابلتين للقراءة | تتوقف التهيئة وتظهر حالة استرداد. لا تُولّد كلمات مرور جديدة لتثبيت يحتوي بيانات. |
| بدء عملية ثانية على مجلد البيانات نفسه | يمنعها قفل ملف يحتفظ به التطبيق طوال التشغيل، قبل قراءة الإعدادات أو إصلاحها. يتحرر القفل عند إنهاء العملية أيضًا. |
| مستخدمون محفوظون لكن `activated=false` | يُتحقق من قاعدة البيانات ويُستكمل التفعيل الموجود دون إعادة إنشائها. |
| حسابات المستخدمين ناقصة مع وجود سجلات أخرى | تظهر حالة استرداد وتُخفى خيارات التفعيل الجديد. يفحص مسار التفعيل نفسه وجود السجلات قبل السماح بأي إعادة تهيئة. |
| فشل حفظ علم التفعيل | تبقى حالة الذاكرة غير مفعلة؛ لا يُعلن اعتماد التفعيل قبل نجاح الحفظ. |
| استرجاع الإعدادات تلقائيًا | يظهر تنبيه في شاشة الدخول ليتحقق المسؤول من البيانات وينشئ نسخة احتياطية حديثة. |

التلف الأصلي ما زال موثقًا في [تحليل الجلسة السابقة](backup_restore_and_runtime_analysis_2026-11-12.md). إصلاح الكتابة يقلل فرصة التلف ويسمح بالتعافي؛ لا يثبت السبب المادي للحادث السابق ولا يضمن سلامة قرص يتعطل أو يتجاهل طلب تثبيت الكتابة.

## التغييرات المكملة في هذه الجلسة

- في `src-tauri/src/runtime.rs`: فصل استكمال التشغيل ليمكن اختباره مع MySQL حقيقي، وتوحيد فحص وجود السجلات بين بدء التشغيل والتفعيل، واعتماد حالة التفعيل في الذاكرة بعد نجاح الحفظ.
- في `src/views/activation/ActivationView.vue` و`src/views/auth/LoginView.vue`: عنوان مناسب لحالة تعذر التشغيل، وإظهار تنبيه الإصلاح التلقائي.
- في `.gitignore`: تجاهل الملفات المؤقتة ونسخ الإعدادات التالفة المؤرشفة لأنها قد تحتوي بيانات اتصال.
- إضافة اختبارات للملفين المصفّرين معًا، وفشل اعتماد التفعيل، ومنع العملية الثانية قبل إصلاح الملفات، وتحرر القفل بعد إنهاء عملية فعلية.
- في `scripts/test-isolated-mysql.ps1`: إعداد حساب الاختبار المحلي بواسطة ملف بدء مؤقت. كانت المحاولتان الأوليان تتوقفان قبل تشغيل الاختبارات لأن `root@127.0.0.1` غير موجود مع `skip-name-resolve`؛ تم إصلاح السكربت.
- إضافة `scripts/verify-runtime-recovery.mjs` لفحص عرض الواجهات الفعلية دون فتح Tauri أو إرسال طلبات إلى قاعدة بيانات.

## التحقق

```powershell
# من src-tauri
cargo test --offline --lib
cargo fmt --all -- --check

# من جذر المشروع
.\scripts\test-isolated-mysql.ps1 -TestFilter runtime::tests
npm.cmd run verify:runtime-recovery
npm.cmd run lint
npm.cmd run build
```

- اختبارات Rust العادية: 46 ناجحة؛ الاختبارات التي تحتاج MySQL أو ملفات مساعدة تبقى مستثناة من التشغيل العادي.
- اختبارات التشغيل باستخدام MySQL المعزول: 4 ناجحة، دون أي فشل.
- اختبار التشغيل المعزول يتحقق من إعادة تشغيل MySQL والخدمة بعد تصفير الملفين، ويقارن المستخدمين وكلمات مرورهم المشفرة والمرضى وإعدادات العيادة قبل العطل وبعده.
- اختبار القفل يستخدم عملية ثانية فعلية، ثم ينهيها ويتحقق من إمكان حجز القفل مجددًا.
- فحص الواجهات يتحقق من التثبيت الجديد، وخمس حالات فشل تخفي خيارات التهيئة والاستعادة، وتنبيه الاسترداد في شاشة الدخول.
- نجح فحص ESLint وبناء الواجهة.

الاختبار يحاكي الملفات التالفة والتوقف بالقوة لعملية الاختبار؛ لم يُفصل التيار عن الجهاز. جميع بيانات الاختبار مصطنعة وموجودة في مجلدات مؤقتة منفصلة، ولم تُستخدم بيانات العميل في هذه الاختبارات.

## تطبيق الإصلاح

الإصلاح موجود في كود المشروع. النسخة المثبتة والمفتوحة لا تتغير تلقائيًا؛ تحتاج الحماية إلى بناء جديد وتحديث التطبيق في وقت مناسب. يبدأ إنشاء نسخة الإعدادات المحمية عند أول تشغيل ناجح للبناء الجديد. لم يُبنَ أو يُثبت مثبت Windows جديد ضمن هذه الجلسة.
