# ملاحظات UI UX Pro Max

## ما تم الاستعلام عنه

| المجال | الاستعلام | القرار |
|---|---|---|
| UX | `keyboard focus modal` | اعتماد focus ring ظاهر، ترتيب tab منطقي، وعدم حجب العنصر المركّز خلف topbar أو footer ثابت. |
| UX | `dashboard loading skeleton` | اعتماد skeleton ثابت الأبعاد مع `aria-busy` ومنع قفز المحتوى. |
| Vue | `rtl dashboard tables forms` | لم توجد نتيجة موثقة؛ أُعيد البحث باستعلام أضيق. |

| Typography | `Arabic admin readability` | رُفضت اقتراحات الخطوط الخارجية؛ المشروع يعمل محليًا ومصدر الحقيقة يحدد IBM Plex Sans Arabic المستضاف محليًا. |
| UX | `status chip icon text color` | اعتماد نص الحالة الصريح مع حدود واضحة وتباين دلالي؛ الأيقونة رُفضت لاحقًا حسب توجيه المستخدم، والنص يمنع الاعتماد على اللون وحده. |
| Vue | `status badge component` / `icon label component` | لم توجد نتيجة موثقة بعد إعادة البحث؛ استُخدمت إرشادات UX العامة ومكوّن Vuetify المشترك القائم بدل اختراع مكوّن خاص بكل صفحة. |

## ما تم اعتماده

- أولوية الوصول: تباين 4.5:1، focus واضح، أسماء مسموعة للأزرار الأيقونية، وعدم الاعتماد على اللون وحده.
- skeleton بدل شاشة فارغة أو spinner طويل، مع حجز مساحة المحتوى.
- أهداف تفاعل 44px على الأقل، وانتقالات قصيرة لا تغيّر geometry.
- جداول للأعمدة المقارنة فقط، وقوائم/cards للأنشطة والملخصات.
- تقليل المخططات: لا يُضاف chart إلا إن كشف علاقة لا توضحها الأرقام أو الجدول، وغالبًا بحد أقصى واحد في الشاشة.
- حالات النظام تستعمل StatusChip مشتركًا بحد كامل وtint دلالي ونص صريح بدون أيقونات؛ نسخة الطباعة الكلاسيكية تبقى معزولة عن واجهة التطبيق.

## ما تم رفضه ولماذا

- لوحة Healthcare المقترحة من المهارة: مصدر الحقيقة هو `tokens.css` في هذا المجلد.
- Noto Naskh/Inter/Fira: الخط المعتمد IBM Plex Sans Arabic، ولا طلبات شبكة أو CDN.
- shadcn/Tailwind: المشروع Vue 3 + Vuetify، وإعادة بناء stack ليست مطلوبة ولا تخدم الحفاظ على السلوك.
- قواعد mobile-native الخاصة بالـsafe areas وhaptics وbottom navigation: المنتج تطبيق desktop/web إداري.
