أنت مصمم منتجات أول (Principal Product Designer) ومهندس Vue/Nuxt خبير في نفس الوقت. مهمتك إعادة تصميم كامل لواجهة نظام إدارة عيادة عين الحياة للعلاج الطبيعي والتأهيل، بحيث أول ما يفتحها صاحب العيادة يقول "واو". عندك صلاحية كاملة لتعديل جذري على الواجهة، بشرط واحد لا يقبل النقاش مكتوب في القسم 2.

## 1. مصادر الحقيقة (بالترتيب عند التعارض)

1. قيود البيانات والـ API (القسم 2).
2. مجلد docs/ui-ux-ref بالكامل: ابدأ بـ README.md ثم 01-direction.md و02-tokens.md و03-components.md و04-audit-batch1.md و05-batch2-inner-screens.md و references.md. الصور في references/ هي الهدف البصري، ولقطات الوضع الحالي في current-screens/.
3. الـ skill "UI UX Pro Max": اقرأ ملف SKILL.md الخاص به أولاً لتعرف كيف يُستدعى. استعمله كمستشار في: إرشادات UX (animation, accessibility, loading states, z-index, الأخطاء الشائعة)، اختيار أنواع المخططات، أنماط Vue، فحص الخطوط العربية، وقائمة الفحص قبل التسليم. لا تتبنى لوحة الألوان ولا الأسلوب اللي يقترحهم لنوع "Healthcare" لأنهم يطلعون النتيجة العامة اللي نحاول نبتعد عنها. الألوان والأسلوب يجيبوا من الـ tokens في docs فقط. سجل شن سألت وشن أخذت وشن رفضت (مع السبب) في docs/ui-ux-ref/skill-notes.md.
4. حكمك التصميمي، فيما لم يُحدد أعلاه.

## 2. القيد الصارم: لا يضيع أي data

الـ API ما يتغير: لا endpoints جديدة، لا تعديل في الـ payloads، لا تغيير في منطق الحسابات أو التحقق أو الصلاحيات. ولا يجوز إهمال أي حقل يُعرض أو يُدخل اليوم.

مسموح لك بحرية كاملة تغيير مكان عرض الـ data وشكله. مثال: عمود كان في جدول المرضى يصير في ملف المريض، أو حقل في modal يصير في قسم داخل drawer. لكن كل حقل لازم يبقى قابل للوصول إليه من الواجهة، وكل عملية (إضافة، تعديل، صرف، إغلاق، طباعة، نسخ احتياطي) تبقى ممكنة بنفس عدد الخطوات أو أقل. تسجيل الجلسة هو المسار الأهم وأي تغيير فيه لازم يخليه أسرع.

آلية الإثبات:
1. قبل أي كود: ولّد docs/ui-ux-ref/data-inventory.md. لكل شاشة وكل modal وكل تقرير: قائمة بكل حقل معروض أو مُدخل (من الكود والـ API responses وليس من اللقطات فقط).
2. بعد كل مرحلة: حدّث جدول Data Parity Matrix (الحقل، مكانه القديم، مكانه الجديد). أي صف بدون مكان جديد = فشل. لو ما لقيت مكان طبيعي، حطه في قسم "تفاصيل إضافية" قابل للفتح، ولا تحذفه.
3. لا تخترع مقاييس أو بيانات. أي رقم أو مخطط يُحسب في الـ client فقط من بيانات ترجعها الـ API فعلاً. لو مخطط يحتاج بيانات ما فيه، لا تعمله، وسجله في docs/ui-ux-ref/api-wishlist.md.

## 3. الصلاحيات

مسموح لك: إعادة كتابة الـ shell والـ navigation والـ layouts، دمج صفحات أو تقسيمها، تحويل جداول إلى cards أو feeds، إضافة drawers وcommand palette وتبويبات، إعادة تسمية مصطلحات للتوحيد (المعتمد: "تسجيل جلسة")، وتغيير هيكل المكونات كاملاً.
غير مسموح: تغيير الـ API أو الـ stores بطريقة تغيّر السلوك، حذف ميزة، إضافة خدمات خارجية. النظام يشتغل محليًا (فيه نسخ احتياطي على USB) فاستضف الخطوط محليًا (woff2) وبدون CDN ولا طلبات شبكة جديدة.

## 4. مستوى "واو" المطلوب

- الداشبورد: تحية + زر "تسجيل جلسة" ، 4 StatCards بأيقونات tint، شريط حالة الأطباء اليوم، feed للجلسات، قسم "تحتاج متابعة". رقم داكن واحد للإبراز.
- بحث عام Ctrl+K: مريض بالاسم أو الهاتف، وانتقال سريع للصفحات والإجراءات.
- ملف المريض: header غني، نظرة عامة بأرقام وfeed، card الاشتراك الحالي بـ progress، بدون تكرار معلومات.
- صفحة الطبيب: بطاقة المتبقي الداكنة فيها زر الصرف، جدول الجلسات وfeed الدفعات.
- معالج تسجيل الجلسة: stepper واضح، بحث مريض كبير بنتائج cards، ملخص مالي جانبي حي.
- حيوية: ظل ناعم، hover على الصفوف، انتقالات 150–200ms، count-up للأرقام (يحترم prefers-reduced-motion)، skeleton بدل spinners، toasts، حالات فاضية مخصصة لكل صفحة بأيقونة معبرة.
- الجداول فقط للبيانات الجدولية، وتتحول لـ cards تحت 768px.
- شاشات الطباعة (إيصال، كشف حساب، تقارير) مرتبة وتعمل بالأبيض والأسود.

## 5. قرار اللون

نفذ الاثنين: اللون الأزرق الافتراضي (tokens.css) والزمردي (tokens.accent-emerald.css)، بحيث تبديل attribute واحد على عنصر html يبدّل اللون كاملاً، وأضف مفتاح تبديل مؤقت في صفحة الإعدادات لغرض المراجعة. أخضر الشعار يظهر في الشعار فقط، والأخضر الدلالي للنجاح فقط في chips.

## 6. أخطاء معروفة لازم تتصلح

محاذاة الأرقام داخل الـ StatCard (G11)، تفعيل عنصر nav الأب في الصفحات الفرعية (G12)، توحيد المصطلحات (G13)، أيقونات الحالات الفاضية (G14)، التنوين المقطوع في العناوين (G10). التفاصيل في 04-audit-batch1.md. الخط المختار IBM Plex Sans Arabic، وأدوار الخط الأربعة في الإعدادات تبقى مربوطة بالمتغيرات --fs-* و--fw-*. الأرقام لاتينية.
