# خطة إعادة بناء الواجهة

## خط الأساس

- التطبيق Vue 3 + Vuetify 3 داخل Vite/Tauri، RTL عربي، والخط IBM Plex Sans Arabic متوفر محليًا.
- الـAPI والـstores والـroutes ناضجة، ولا تحتاج إعادة تصميم منطقي.
- توجد إعادة تنسيق سابقة غير مثبتة تعتمد الأخضر كلون واجهة وتخالف المرجع الحالي الذي يخصص الأخضر للنجاح والشعار.
- لا توجد تغييرات مطلوبة على endpoints أو payloads أو قواعد الحساب والصلاحيات.

## مراحل التنفيذ

1. **الأساس:** نقل tokens المرجعية إلى `src/styles/tokens.css` مع aliases انتقالية، تحديث Vuetify defaults، AppShell، PageHeader، EmptyState، StatusChip، StatCard، DataTableCard وحقول النماذج.
2. **المسارات اليومية:** Dashboard، تسجيل الجلسة، الجلسات، المرضى وملف المريض، الاشتراكات.
3. **الإدارة والمالية:** الأطباء، الخدمات، الجهات الراعية، المشتريات والإيجار، التقارير.
4. **النظام:** المستخدمون، سجل التدقيق، الإعدادات، تسجيل الدخول، الطباعة.
5. **التلميع:** responsive، keyboard، loading/error/empty، 50+ صفًا، print، contrast، lint/build/verification ولقطات before/after.

## قرارات تنفيذية

- اللون الافتراضي أزرق. `data-accent="emerald"` على عنصر `html` يبدّل accent فقط للمراجعة.
- الحفاظ على aliases الحالية للـCSS خلال الانتقال لمنع تشوه الشاشات غير المنقولة بعد.
- لا تُحذف أي معلومة. نقل الحقول مسموح بشرط بقائها قابلة للوصول.
- صفحة التفاصيل تبدأ بـ header غني ثم ملخص ثم tabs؛ الجداول داخل التبويبات التي تحتاج مقارنة فقط.
- Charts قليلة جدًا، وتُرفض إن كان StatCard أو feed أو جدول يشرح البيانات بوضوح أكبر.

## تعريف الإنجاز لكل شاشة

- تطابق بيانات كامل مع الجرد ومصفوفة النقل.
- إجراء رئيسي واحد، hierarchy واضح، RTL سليم، ولا breadcrumb مكرر.
- حالات loading/error/empty وكثرة البيانات.
- keyboard وfocus وcontrast وتجاوب 768/1024.
- لا قيم ألوان خام داخل المكونات ولا قواعد تصميم خارج tokens.
